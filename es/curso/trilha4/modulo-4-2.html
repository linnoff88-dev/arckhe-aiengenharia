MÓDULO 4.2

📚 Biblioteca Viva

De una colección desordenada a un sistema curado: organizar, nombrar, versionar y retirar, para que tu biblioteca crezca sin convertirse en un archivo muerto. Incluye el atajo para quienes llegan tarde y cómo cada profesión usa el método.

1

🗂️ Organizar: prompts, briefings y playbooks en un solo lugar

La biblioteca no necesita ser sofisticada para funcionar. Necesita ser plana y fácil de encontrar. Una jerarquía demasiado profunda acaba con la adopción: nadie recuerda en qué subcarpeta de otra subcarpeta guardó algo. Tres carpetas, un índice.

📁

/prompts

Inputs probados, listos para reutilizar. Un prompt por archivo. Nombre con situación y versión.

📋

/playbooks

Procesos de 1 página con pasos, prompt estándar y métricas. El corazón de la biblioteca.

📄

/briefings

Contextos reutilizables: quién es el cliente, cuál es el estilo de voz, cuáles son las restricciones del proyecto.

2

🏷️ Nombres y versiones (v1, v2, campeón actual)

El nombre es la interfaz de tu biblioteca. Si no puedes encontrar algo en 10 segundos, la convención de nombres falló. La regla es simple: [lo-que-hace]-[situación]-v[número]. Opcionalmente, agrega "-campeao" a la versión que más usas.

✓ Nombres que funcionan

  • post-gancho-linkedin-v3
  • email-cliente-bravo-v2
  • playbook-onboarding-freelancer-v1
  • resumo-reuniao-executiva-v4-campeao

✗ Nombres que no funcionan

  • buen prompt
  • template FINAL (2)
  • copia de la copia del correo
  • usar este

Regla de oro del versionado

Nunca borrar — jubilar. La versión antigua es el historial de aprendizaje. Moverla a /aposentados mantiene limpio el índice sin perder el recorrido de evolución. Dentro de 6 meses agradecerás haber guardado la v1.

3

✅ Listas de verificación a partir de procesos repetidos

El checklist no es burocracia: es memoria externalizada. Cuando ejecutas un proceso que depende de no olvidar pasos críticos, una lista de verificación ahorra errores y retrabajo. Nace de la repetición, no de la teoría.

✓ Procesos que requieren una lista de verificación

  • ✓ Publicación de contenido (revisar, dar formato, programar)
  • ✓ Entrega al cliente (revisar, versionar, enviar)
  • ✓ Inicio de proyecto (briefing, acceso, carpeta)
  • ✓ Cualquier proceso con un paso que ya hayas olvidado antes

✗ Cuándo no ayuda una lista de verificación

  • ✗ Proceso creativo sin pasos fijos
  • ✗ Tarea única e irrepetible
  • ✗ Checklist tan largo que nadie lo lee hasta el final
  • ✗ Pasos obvios que no corres el riesgo de olvidar

💡 La regla de las 3 ejecuciones

Si ejecutaste el mismo proceso 3 veces de manera similar, es hora de crear una lista de verificación. Antes de 3, todavía estás descubriendo los pasos. Después de 3 sin una lista de verificación, estás memorizando algo que podrías tener documentado.

4

🧹 Curaduría: retirar lo que dejó de funcionar

Una biblioteca que solo crece se convierte en un archivo muerto. La curaduría trimestral es lo que mantiene el sistema vivo y navegable. Son 15 minutos cada 3 meses, sin ceremonias, reuniones ni consultoría.

1

¿Usé esto el último trimestre?

Si la respuesta es no: muévelo a /aposentados. No lo elimines: el historial tiene valor para ver de dónde vienes y evitar volver a empezar cometiendo el mismo error.

2

¿Sigue funcionando tal como está escrito?

Si el contexto cambió (nueva herramienta, nuevo cliente, nuevo formato), actualiza el prompt o playbook y sube la versión. Nunca edites sin versionar.

3

¿Hay algo mejor que haya aprendido desde la última versión?

Si la respuesta es sí: crea una nueva versión con la mejora y conserva la anterior como historial. El proceso evoluciona sin perder el registro del aprendizaje.

4

¿Debería compartirse este proceso?

Si funcionó de manera consistente y otra persona podría usarlo: candidato a compartirlo con el equipo, un cliente o como contenido público.

Cuándo hacer la curaduría

Pon un recordatorio recurrente cada 3 meses. Duración: máximo 15 minutos. Si tarda más, la biblioteca creció demasiado rápido: es señal de que debes ser más selectivo al incorporar elementos.

5

🤝 Compartir con el equipo/clientes

Una biblioteca compartida es activo de autoridad. Cuando puedes entregarle al cliente no solo el resultado, sino también el proceso, dejas de ser un proveedor y te conviertes en un socio estratégico. Lo mismo vale dentro del equipo.

Compartir con el equipo

  • → Incorporación de una persona nueva: enlace a los playbooks relevantes
  • → Uniformiza los estándares sin necesidad de una reunión de coordinación
  • → Los errores individuales se convierten en aprendizaje colectivo
  • → Alguien mejora un proceso y todos se benefician

Compartir con clientes

  • → Informe mensual + el playbook del proceso entregado
  • → Muestra el método, no solo el resultado: una ventaja difícil de copiar
  • → El cliente entiende el valor y es más fácil mantener el contrato
  • → Abre una conversación sobre cómo escalar el proceso

💡 Biblioteca como contenido

Si creas contenido público, tus playbooks son material para crear contenido. "Mi proceso para X" es uno de los formatos que más genera interacción, porque ofrece el método junto con el resultado.

6

⚡ Atajo del rezagado: los 3 prompts que más usas

No esperes a tener 30 elementos en la biblioteca para empezar. El el mínimo viable es 3. Piensa en los 3 prompts que más usas: los que abres con frecuencia o siempre vuelves a crear desde cero porque no recuerdas dónde los guardaste.

Cómo identificar los 3 primeros

  • → ¿Qué prompt recreas desde cero cada semana?
  • → ¿Qué tarea te lleva más tiempo porque «tienes que recordar cómo se hace»?
  • → ¿Qué proceso ya le explicaste a alguien más de una vez?

Qué hacer con ellos

  • 1. Escribe cada uno en 1 párrafo sencillo
  • 2. Ponle un nombre con la convención [o-que-faz]-v1
  • 3. Guárdalo en la carpeta correcta (/prompts o /playbooks)

El método es universal. La biblioteca es específica. Mira cómo cada perfil construye la suya y úsala como referencia para imaginar cómo sería la tuya después de 1 año de uso constante.

Resumen del Módulo 4.2

  • ✓ Estructura de 3 carpetas: plana, fácil de navegar, sin jerarquías que nadie mantiene.
  • ✓ Convención de nombres: [lo-que-hace]-[situación]-v[número]. Lo bastante simple para perdurar.
  • ✓ Los checklists nacen de la repetición: regla de las 3 ejecuciones iguales.
  • ✓ Una curaduría trimestral de 15 min mantiene viva la biblioteca y evita que se convierta en un archivo muerto.
  • ✓ Una biblioteca compartida es un activo de autoridad: onboarding, diferenciación y contenido.
  • ✓ Atajo para rezagados: empieza con 3. La complejidad viene después de comprobar el valor.
  • ✓ Cada profesión tiene su biblioteca: el método es el mismo, el contenido es específico.
